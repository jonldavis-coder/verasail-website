Agentic AI, generative AI and RPA

Generative AI produces a draft, RPA repeats a scripted path, and agentic AI pursues a goal across steps and tools. The useful question is which job a step actually needs.

By Verasail LLC · Published November 16, 2026 · 9 min read

Generative AI, RPA and agentic AI get talked about as if they were three brands of the same product. They are three different jobs. Generative AI produces a draft from a prompt. Robotic process automation, usually shortened to RPA, repeats a path you defined in advance. Agentic AI pursues a goal across steps and tools, and stops to ask when the next step is not one it should take alone. Useful systems often use more than one. The expensive mistake is buying one label when the work needs another.

Three different jobs

A label is useful when it tells you what the software is allowed to decide. Generative AI is allowed to produce language, images, code or another artifact from the context you provide. On its own, it stops there. RPA is allowed to carry out a path you already wrote: open this, read that, type this, submit. It is not asked to invent the path. An agent is allowed to choose among permitted steps to reach a goal, inside limits you set, and to hand the work to a person when those limits run out. Our guide to what an agentic AI workforce is starts from that third permission.

What generative AI is good at

Generative AI, often shortened to GenAI, takes context and produces something new. That might be a summary of a long thread, a first pass at a user story, a plain-language version of a policy, release notes, or the narrative section of a weekly pack. The strength is fluency with unstructured information. You can hand it a messy pile and ask for a clean draft in the format your team already uses.

The limit is the stopping point. A generative model used on its own does not log into your systems, file the record, or know whether last week's figure is the one the business still trusts. It also does not enforce an approval rule unless you build a separate step for that. A prompt is a weak place to keep a control. Treat the output as a draft that a person or a later check accepts. Fluent is not the same thing as approved.

What RPA is good at

RPA records or codes a sequence and then repeats it: open this, read that, type it there, submit, and log the run. It fits when the process is stable, the rules are known, and the screens or interfaces change rarely. Moving a completed form into a system of record is the classic case.

RPA struggles when the input is unstructured or the path is not known in advance. A renamed button, a new layout, or an exception that was never written down stops the run, or finishes the wrong path because nothing told it to halt. That brittleness is the trade you accept for predictability. For stable work, predictability is what you want: you can say, before it runs, what done looks like for every case you intend to handle. If you cannot write the path down, write it before you automate the movement.

What agentic AI adds

An agent is given a goal, a role and permission to use a defined set of tools. It can break the goal into steps, choose a tool, read the result and decide the next step. If a step fails, it can try another path that is still inside its permissions, or stop and hand the work to a person. That discretion is the reason to use an agent. It is also the reason the limits have to be designed, not hoped for.

Take a weekly portfolio pack. A script or an API job can pull the figures from the systems you named. A generative model can draft the narrative from those figures and from notes people already wrote. An agent can notice that one initiative has no update, ask the retrieval step to retry, and hold the pack because the gap crosses a rule a person set. The agent is the part that coordinates the others and knows when to stop. A script fails visibly when a button moves. An agent can choose a plausible next step that is still a bad business action, which is why the permissions, the handoff and the record of what ran have to be designed. That coordination layer is what we describe in AI orchestration hub explained.

Where they overlap

An agent usually calls a generative model when it needs language, and a script or an API when an action must happen the same way every time. Ask which part is allowed to decide. If every branch is written in advance, you have automation with a language step. If the system may choose among permitted actions to reach a goal, you have an agent, and you need the oversight that goes with discretion. The Orchestration Hub is built for that second case: routing, sequencing and human handoff, with one view of what ran. The agentic workforce framework applies the same idea to a team of roles.

How to choose for one workflow

Apply this filter to a single workflow. It is a poor scorecard for a whole company.

  • Choose generative AI when the deliverable is a draft and a person will review it. Summaries, first-pass writing and turning rough notes into a structured document fit here.
  • Choose RPA or another script when the path is stable, the rules are explicit and you can name every case you intend to handle. Copying, filing and refreshing known fields fit here.
  • Choose an agent when the work has a goal, the path varies, more than one system is involved, and a person still needs to stop or approve the steps that are hard to undo.
  • Choose to wait when the process is not written down. Write the steps and the definition of a good result first.

A single workflow often needs all three, applied to different steps. Our strategy consulting work is mostly this sorting, and the transformation roadmap keeps a pilot from starting on the hardest step.

A sensible combination

You do not need one platform decision on day one. For a recurring process, a practical sequence is:

  1. Script the stable movements so people stop retyping the same fields.
  2. Use generative AI for the language those steps produce: the summary, the narrative, the reply draft.
  3. Put an agent in charge only where the next step varies and the choice has a real payoff, with a person on the steps that carry risk.
  4. Keep one place to see what ran, what was handed to a person, and whether the result stayed inside the rules. Telemetry is that view.

Name the roles before you add the agent. AI agent roles is a one-page contract for each job. Check the inputs before you trust the output. Data quality for AI agents covers that check. An agent coordinating unfit inputs will publish a confident pack that nobody should send.

What to put in place before you scale

  • A named owner. Someone can explain what the automation is for and can turn it off.
  • Permissions. Each script and each agent can touch only the systems the job needs.
  • A review point. A green log is not a correct business outcome. Place the review where a person can still change the result. The human-in-the-loop checklist is a way to place it.
  • Change control. When a screen, a field or a policy changes, someone updates the script or the instructions on purpose.
  • People who can direct the work. Retraining knowledge workers belongs in the rollout, because someone has to review the draft and handle the exception.
